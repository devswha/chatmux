# 접속 중단 근본 수정과 모바일 회귀 검증 — 2026-09-05

## 접속 중단 원인

운영 중인 1.8.18에서 HTTP 연결은 성립했지만 `/health`도 응답하지 않았다.
프로파일링 결과 Codex 기록의 마지막 완료 답변을 찾는 역방향 검색이 CPU 한
코어를 점유하고 있었다. 청크의 첫 바이트가 줄바꿈이면 검색 위치가 0이 된 뒤
`Buffer.lastIndexOf(..., -1)`이 끝으로 되돌아가 같은 구간을 반복했다.
재시작은 접속을 복구했으며, 영구 수정은 PR #112에 반영했다.

## 수정한 동작

| 영역 | 재현한 문제 | 수정과 회귀 검사 |
|---|---|---|
| Codex 제목 검색 | 청크 시작의 줄바꿈에서 무한 반복 | 검색 위치가 0이면 종료. 별도 프로세스의 제한 시간으로 회귀가 테스트 실행기까지 멈추지 않도록 검사 |

| Codex 제목 우선순위 | 공백뿐인 인덱스 이름이 정상 완료 답변의 제목을 가림 | 공백 이름을 비어 있는 이름으로 처리하며 유효한 인덱스 제목의 우선순위는 유지 |

| 다음 메시지 | 대기 메시지가 새로운 입력과 당시 모델 설정을 덮어씀 | 대기 메시지의 본문·설정을 독립적으로 전달. 실패하거나 교체된 업로드는 해당 큐를 보존하며 자동 재시도하지 않음 |

PR #113에는 모바일 화면 수정과 CUA 개선을, PR #114에는 Astra xhigh 병렬
검토에서 재현한 기록 처리·초안·전환 관련 수정을 반영했다. 연속 제출과 첨부
소비의 후속 수정은 1.8.19 준비 변경에 포함한다.

## 검증 방식

- `npm run verify`로 감사, TypeScript, Rust, 전체 서버·클라이언트 테스트,
  실제 tmux/PTY 검사, lint, 제품 식별 검사와 빌드를 실행한다. PR의 Node 22·24
  및 canonical server bundle 검사는 최신 main을 포함한 변경에서 통과해야 한다.
- Codex 회귀는 빈 줄, 청크 경계, 여러 청크의 큰 줄, UTF-8 분할, 잘린 JSON,
  빈 파일, 제목 우선순위를 검사한다. 시간 제한은 무한 반복 중인 자식 프로세스
  밖에서 적용하며, 성능 검사는 실행 시간 대신 누적 복사 바이트를 제한한다.
- React 테스트 렌더러에 마운트한 composer에서 지연 응답과 타이머 실행 순서를
  제어한다. 화면 전환, 읽기 전용 전환, 큐 교체, 새 입력·새 첨부, 저장 실패,
  명시적 재시도를 검사한다.
- `npm run cua:mobile`은 320px·390px 터치 화면에서 메뉴, 긴 입력, 가로 회전,
  짧은 viewport, 크기 조절, 지정된 fake tmux pane으로의 전송과 Chat/CLI 전환을
  검사한다. Chrome/WebKit의 38개 검사와 별도의 기존 웹 E2E 30개를 실행했다.
  WebKit 18 및 26.5에서도 모바일 검사를 확인했다.
- 설치형 PWA는 별도 HOME·프로필·DBus·GNOME·Xvfb에서 검증한다. 서비스 워커,
  설치 아이콘, 호스트별 deep link, 알림 권한과 실제 OS 알림 전달을 확인한다.
  테스트용 Chrome에는 운영 계정이나 브라우저 프로필을 사용하지 않는다.

## 검증 도구에서 함께 고친 문제

격리 GNOME의 잠금 해제된 키 저장소가 없어서 Chrome의 첫 탐색이 멈췄다.
자격 증명을 담지 않는 임시 프로필에만 basic password store를 지정했다.
창 포커스는 테스트가 시작한 Chrome PID의 창을 명시적으로 선택한 뒤 검사한다.
이후 격리 PWA/OS 검사도 통과했다.

CUA의 두 보호 hook에 대한 무결성 검사는 과거 릴리스의 고정 해시 대신 검증
대상 커밋과 작업 파일을 비교한다. 임시 Git 저장소 회귀로 승인된 커밋은 통과하고, 실행 중
발생한 미커밋 수정은 실패함을 확인한다. 최종 요약에는 모바일 결과·이미지와
Node 22·24 및 번들 CI 영수증도 필요하다. 영수증이 아직 없을 때의 실패를
전체 검증 성공으로 취급하지 않는다.

## 릴리스와 검증 범위

1.8.19는 package.json과 lockfile의 두 버전 필드, 정확한 호환성 선언을 함께
갱신한다. 스키마 세대는 20이며 1.8.17·1.8.18의 호환 구간을 유지한다.
이미 발행된 1.8.18 태그의 선언과 migration registry에 대조해 준비 메타데이터를
검증했다. 발행 경로는 기존 Release ChatMux Server workflow 하나이며, 설치는
그 canonical archive와 검증된 updater를 사용한다.

브라우저의 모바일 에뮬레이션과 실제 모바일 기기 검증은 구분한다. 물리적인
iPhone/Android 기기의 키보드 및 네이티브 푸시 동작을 검증했다고 주장하지 않는다.
테스트에는 합성 기록과 격리된 fake agent만 사용했으며, 운영 기록·키·인증 정보는
보고서나 테스트 자산에 포함하지 않았다. 기존 SSH/DB 작업의 미커밋 변경 34개도
이 수정에 섞지 않고 보존했다.
